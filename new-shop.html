Add a Shopper shop, step by step

Example: shopper3 at shop3.hsaverse.shop. Run everything on the server as root in /srv/stack. Every script is safe to re-run: steps that are already done are skipped.

0. Instance file (new names only)

Every shop needs its own instances/<name>.env in the stack repo. Without it, show-config.sh says ERROR: no instances/<name>.env. shopper3 and solemenders already have one, so skip this step for them. For any other name, do this on your PC, not on the server, or the next git pull there will conflict:

  1. Pick a name: lowercase letters, numbers and _ only. It becomes the Linux user, the database and /srv/apps/<name>.
  2. Find the next free Redis pair (the highest number shown, plus 1 and plus 2): 
    grep -h "^REDIS" instances/*.env | sort -t= -k2 -n | tail -2
  3. Copy an existing file and change APP_NAME, DB_NAME, DB_USER (= the name), REDIS_DB, REDIS_CACHE_DB, SERVER_NAME and REPO_URL: 
    cp instances/shopper3.env instances/<name>.env
  4. Commit and push it. Step 2 below brings it to the server.

Redis pairs in use: shopper1 0/1, shopper2 2/3, bagisto 4/5, shopper3 6/7, solemenders 8/9.

1. DNS

At the DNS provider for hsaverse.shop, add an A record: shop3 → 207.180.249.190. Check it:

dig +short shop3.hsaverse.shop

Continue once it prints 207.180.249.190. Otherwise the certificate in step 5 fails.

2. Get the latest stack

cd /srv/stack && git pull

This brings in instances/shopper3.env (database shopper3, Redis databases 6 and 7).

3. Edit .env

sudo nano /srv/stack/.env

Add the name to INSTANCES:

INSTANCES="website shopper1 shopper2 shopper3 odoo"

Add this block under shopper2's, with your own email and password:

# ---------------------------------------------------------------------
# shopper3 — Laravel Shopper
# ---------------------------------------------------------------------
SHOPPER3__SERVER_NAME="shop3.hsaverse.shop"
SHOPPER3__REPO_URL=git@github.com:Khanaliasad/shopper.git
SHOPPER3__REPO_BRANCH=main
SHOPPER3__APPENV_MAIL_FROM_NAME="Shop Three"
SHOPPER3__PHP_VERSION=8.3
SHOPPER3__FPM_MAX_CHILDREN=20
SHOPPER3__QUEUE_WORKERS=2

# shop setup -> php artisan shopper:setup   (run: sudo bin/shopper-setup.sh shopper3)
SHOPPER3__RUN_SHOPPER_SETUP=first
SHOPPER3__SETUP_ADMIN_EMAIL=khanaliasad.aak@gmail.com
SHOPPER3__SETUP_ADMIN_PASSWORD='PutAStrongPasswordHere'   # required: nothing generates it
SHOPPER3__SETUP_STORE_NAME="HSA Verse 3"
SHOPPER3__SETUP_STORE_EMAIL=support@hsaverse.shop
SHOPPER3__SETUP_COUNTRY=PK
SHOPPER3__SETUP_CURRENCIES=PKR
SHOPPER3__SETUP_STREET="Main Rd 1"
SHOPPER3__SETUP_POSTAL_CODE=54000
SHOPPER3__SETUP_CITY=Karachi

Save with Ctrl+O, Enter, then exit with Ctrl+X. Or, after adding the block, replace the password with a random one and print it:

P=$(openssl rand -base64 18 | tr -d '/+='); sudo sed -i "s|^SHOPPER3__SETUP_ADMIN_PASSWORD=.*|SHOPPER3__SETUP_ADMIN_PASSWORD='$P'|" /srv/stack/.env; echo "shopper3 admin password: $P"

4. Check the config

sudo bin/show-config.sh shopper3

Fix any errors it shows before going on.

5. Create the shop

Linux user, folders, database, nginx, PHP-FPM and SSL certificate:

sudo bin/create-instance.sh shopper3 && sudo bin/render.sh shopper3 && sudo systemctl reload nginx && sudo bin/issue-cert.sh shopper3

6. GitHub deploy key

Each shop runs as its own Linux user and needs its own key, even when it uses the same repo as another shop.

sudo -u shopper3 -H ssh-keygen -t ed25519 -N "" -f /srv/apps/shopper3/.ssh/id_ed25519 -C "shopper3@server"
sudo cat /srv/apps/shopper3/.ssh/id_ed25519.pub

On GitHub: Khanaliasad/shopper → Settings → Deploy keys → Add deploy key. Paste the printed line, title it shopper3, and leave write access off. Then trust GitHub and test the key:

sudo -u shopper3 -H ssh -o StrictHostKeyChecking=accept-new -T git@github.com

It should say "successfully authenticated".

7. First deploy

sudo bin/deploy-laravel.sh shopper3 --seed

In order, the deploy:

  1. runs the migrations
  2. runs DatabaseSeeder. On an empty database it first runs Shopper's own seeders (countries, currencies, channel, carriers, payment methods, and the administrator / manager roles), which is what shopper:install would do. Then it runs the app's POS, permission and settings seeders.
  3. runs shopper:setup (admin user and store details), because of RUN_SHOPPER_SETUP=first

Why not shopper:install? It asks questions and waits for answers, and a deploy has nobody to answer them. The deploy never calls it. DatabaseSeeder and shopper:setup do the same work without questions.

The app needs commit 7a3f2b4 or later on main. If it's older, use this instead (empty database only, because these seeders duplicate rows when run twice):

sudo bin/deploy-laravel.sh shopper3 --seed='Shopper\Core\Database\Seeders\ShopperSeeder' --seed='Shopper\Database\Seeders\AuthTableSeeder' --seed

8. Log in

Go to https://shop3.hsaverse.shop/cpanel/login and use the email and password from step 3.

Other names & domains

Example: name asad on qwerty.info. The steps are the same, with these changes:

  • Use lowercase letters, numbers and _ only. The name becomes the Linux user, the database and /srv/apps/asad.
  • On your PC, create instances/asad.env: copy instances/shopper3.env and change APP_NAME, DB_NAME and DB_USER to asad. Set REDIS_DB / REDIS_CACHE_DB to the next free pair (grep -h REDIS instances/*.env; 0–9 are taken, so use 10/11). Commit and push, then do step 2.
  • DNS: at the registrar for qwerty.info, add A records for @ and www → 207.180.249.190.
  • In .env the prefix is ASAD__, e.g. ASAD__SERVER_NAME="qwerty.info www.qwerty.info". Add asad to INSTANCES.
  • In every command, replace shopper3 with asad.

If something fails

ErrorFix
There is no role named `administrator`Shopper's seeders didn't run (app older than 7a3f2b4). Start over below, then deploy with a current app
migrate:rollback: "prohibited from running in this environment"The app blocks destructive commands in production. For a new shop, don't roll back. Start over below
shopper:setup needs at least …_SETUP_ADMIN_EMAIL and …_SETUP_ADMIN_PASSWORDThe password is empty in .env. Set it (step 3) and deploy again
Certificate error in step 5DNS doesn't point to the server yet. Wait, then run sudo bin/issue-cert.sh shopper3
Permission denied (publickey)The deploy key isn't on the repo (step 6)
Cannot find native binding during the buildnpm bug. The deploy retries once by itself. If it still fails, deploy again
403 on /cpanel/git pull, then sudo bin/render.sh shopper3 && sudo systemctl reload nginx

Start over (a new shop that failed)

Deleting /srv/apps/shopper3 by hand is not enough: the database and its tables stay. Remove the app, Linux user and database together. This keeps the SSL certificate and .env. Preview first:

sudo bin/uninstall.sh --apps --databases --dry-run shopper3
sudo bin/uninstall.sh --apps --databases shopper3

Then do steps 5–7 again. The deploy key was deleted with the folder, so remove the old shopper3 key on GitHub and add the new one. Never run this on a live shop: it deletes its orders and customers.
